# S2J Query Pinned Service - サービス仕様 (ドラフト)

採用・合意前の設計メモとして `docs_mod/` に置き、確定後は `docs/SERVICE_SPEC.md` に移行します。

## 概要

本ドキュメントは、S2J Query Pinned Service の初期設計における、サービス全体の統合の見取り図を定義します。

## 目的

一覧 (Archive の Query Loop 相当) で、指定したコンテンツを先頭にピン留めし、残りを別条件で並べるための組立ロジックです。Similarity Service と同型の Composer ライブラリです。

本ライブラリは **WordPress 非依存** です。WP フック、設定画面、`WP_Query` の実行は扱いません。

Query Loop ブロック単体では、先頭固定と残りの独立したソート / フィルターを同時に表現しづらい、というのが出発点です。

## 非目標 (本ライブラリ)

* `add_action` / `register_post_type` / `WP_Query` の実行。
* 管理画面 HTML、ブロック登録、REST エンドポイント。
* テーマの見た目 (色、テンプレート階層)。
* 公開日 / 更新日の算出 (それは [S2J Content Dates Service](https://github.com/stein2nd/s2j-content-dates-service.git))。
* SaaS 送信。

## 機能 (プロダクト観点)

* この記事とこの記事を featured としてピン留めしたい、という要求に応える。
* ピン留め以外は、所定の条件でソート (昇順 / 降順) やフィルターできる。
    * 所定の条件には、S2J Content Dates (または `s2j/content-dates-service`) 由来の更新日も含む。
* 管理画面で、コンテンツタイプごとに次を制御できる (UI はプラグイン)。
    * 利用中の各 CPT にピン留めチェックを出すか。任意タイプだけ出さない指定も可。
    * チェックを出すと指定したタイプの Archive に、ピン留めの有無のフィルター / ソートを足すか。
    * タイプごとにピン留めできる件数の上限。
    * 可能ならメディアライブラリのコンテンツにも対応する。

## Composer ライブラリの理由

要件の見た目は WordPress 機能ですが、層は次に分かれます。

| 層 | 中身 | 置き場 |
| --- | --- | --- |
| 計算 | ピン留め ID を先頭に固定し、残りを渡された順 (またはキー) で N 件取る。ページングでピン済みを重複させない。タイプ上限を超えた分の切り詰め | **本ライブラリ** |
| 副作用 | チェックボックス、CPT ごとの on/off、メタ、Archive クエリー、ブロック、メディア UI | **S2J Query Pinned** (プラグイン) |

プラグイン一本にロジックを置くと、kis-core / ニュース / イベントなどで組立が複製され、ユニットテストも WP 一式が必要になります。

「残り」のソートに更新日が含まれる件は、**本ライブラリが Content Dates を知らない** のが正しいです。プラグインが非ピン集合に `content-dates-service` を適用し、その結果を本ライブラリに渡して結合します。サービス同士は Composer 依存でつなぎません。

kis-core に抱え込まない判断も Content Dates と同じです。横断機能なので S2J 製品として切り出します。

## 本ライブラリの責務

入力は WP オブジェクトではなく、**ID 列と設定のレコード** です。出力も順序付き ID 列 (と、はみ出したピンの扱い結果) です。

| 責務 | 内容 |
| --- | --- |
| 結合 | ピン済みを先頭、残りを呼び出し側が決めた順で続ける |
| 件数 | ページサイズ N、オフセット。ピン済みを2ページ目以降で繰り返さない |
| 上限 | タイプごとの上限を超えたピンは無視、または新しい順などで切り詰め (規則は純関数) |
| フィルター材料 | 「ピンか否か」を呼び出し側が絞り込みキーにできるよう、判定だけ提供。`WP_Query` 自体は組まない |

メディア (`attachment`) も、サービスからはコンテンツタイプの1件です。メディア UI はプラグインです。サービス仕様では入出力の拡張点にとどめ、WP 実装は段階導入でよいです。

## ピン留め件数の上限

WP コアの sticky に上限はありません。一覧先頭の featured としては、次を目安にします。

| 目安 | 理由 |
| --- | --- |
| デフォルト3 | ヒーロー1 + 脇2。ニュース先頭として多い |
| タイプごとに変更可 (UI の推奨レンジは1〜6) | トップと CPT アーカイブで必要数が違う |
| ハード上限10前後 | 除外 ID が増えると残り一覧のページングが壊れやすい。ピンしすぎは先頭固定ではなく別コレクション |

ベストプラクティスは **少なく固定する** ことです。無制限は避けます。ライブラリは上限を超えた分の扱いを純関数で決め、プラグインが設定値を渡します。

## プラグインの責務 (境界。詳細はプラグイン仕様)

指定 UI は、管理画面の **標準テーブル** (`WP_List_Table` 相当) とします。1行 = 1コンテンツタイプです。見出しは「カスタム投稿タイプ」ではなく **コンテンツタイプ** です。Content Dates の表と同型です。

| 表示名 | タイプ | ピン留めチェックを出す | Archive にピン有無の絞り込み / ソートを足す | 上限 |
| --- | --- | --- | --- | --- |
| 固定記事 | `page` | on/off | 原則なし (`has_archive` がないため列は無効) | (任意) |
| 投稿 | `post` | on/off | on/off | 数値 |
| 各 CPT | 登録名 | on/off | on/off | 数値 |
| メディア (任意) | `attachment` | on/off | メディア UI は別でも可 | 数値 |

「テーマで enabled な CPT」は、この表の行の集合です。任意タイプだけ出さない指定は、該当行を off にします。

固定記事を CPT ではないからと別画面にせず、`page` を1行足します。Archive 列は、効かないチェックを置かず無効化します。

プラグインはテーブルの状態を設定レコードに落とし、本ライブラリに渡します。メタ名は KIS 専用の `_kis_pinned` ではなく、S2J 境界に合わせた `_s2j_pinned` 等を検討します (確定はプラグイン仕様)。

## 設計方針

本ライブラリは [kis-wordpress エコシステム仕様](https://github.com/stein2nd/kis-wordpress/blob/main/docs_mod/specs.md) と同じく、FOP + Clean Coding を基本とします。Clean Architecture の定型分割は採用しません。

データの中身は純粋関数と不変レコードに閉じます。

| 借用する原則 | 本ライブラリでの意味 |
| --- | --- |
| 依存の向きは外 → 内 | 純関数は WordPress / HTTP を知らない |
| 内側はビジネスルール | 結合、上限、ページングはフレームワーク非依存 |
| 外側は詳細 | プラグインが WP と本ライブラリの間を翻訳する |

## 関連リポジトリ

呼び出し側の正は **S2J Query Pinned** です。kis-core は本機能の本体にせず、必要なら当該プラグインを有効化 (または require) します。

| 名称 | 種別 | 役割 |
| --- | --- | --- |
| **本ライブラリ** | Composer | ピン優先の ID 列組立、上限、ページング |
| **S2J Query Pinned** (仮) | WP プラグイン | 管理画面、オプション、メタ、Archive の `WP_Query`、ブロック、メディア UI |
| [S2J Content Dates Service](https://github.com/stein2nd/s2j-content-dates-service.git) | Composer | 非ピン集合の更新日ソート等。本ライブラリとは独立 |
| [kis-wordpress](https://github.com/stein2nd/kis-wordpress.git) | モノレポ | サイト専用プラグイン群。ピン機能は kis-core に抱え込まない |
| [kis2026_base](https://github.com/stein2nd/kis2026_base.git) | テーマ | 見た目。一覧の正はプラグイン + 本ライブラリ |

## 実装順 (KIS エコシステムとの関係)

1. 本 repo でスケルトンと純関数の初版 (PHPUnit で WP なし)。
2. S2J Query Pinned プラグインが Composer で require し、テーブル UI とクエリーをつなぐ。
3. 非ピンの更新日ソートがいる画面では、プラグインが Content Dates の結果を本ライブラリに渡す。
4. KIS サイトでは当該プラグインを有効化し、kis-news 等と共用する。
5. 旧案の `packages/query-pinned-service/` 仮置きは、本 repo へ寄せる (モノレポ仕様の更新は kis-wordpress 側)。

## 未決 (次の仕様で確定)

* 上限超過時は「無視」か「新しい順で切り詰め」か。ピン操作時点で弾くかはプラグイン。
* 新規に登録されたコンテンツタイプのデフォルトは on か off か。デフォルト上限は3でよいか。
* ハード上限をライブラリ定数にするか、プラグイン設定の最大値にするか。
* ピン同士の順序 (チェック順、明示的な並び、日付)。
* タイプのデフォルトに加え、個別コンテンツ以外の「この一覧だけピンセットが違う」を持つか。
